Smart home control
Lights, sockets, thermostats, locks — per zone
Always on
Cost on every request —
The core of the assistant: zones, device types, reading states and setting on/off, brightness, temperature and locks. Always enabled — this is the base cost every configuration pays. It includes the assistant's behavior rules, the current time, and the "what can you do?" helper.
Look in other zones when this one has none
On (default): if you ask for something the voice device's own zone does not have, the assistant uses the matching devices in the only other zone that has them — say "close the sunshade" in the kitchen and it closes the one on the terrace. It never does this when several zones have such devices; then it still asks you to say "everywhere".
Allow unlocking by voice
Off (default): the assistant can lock doors but never unlock them. Anyone within earshot of a device can talk to it — only enable this if you accept that.
Find devices with Jev (TypeSafe)
Off (default): the AI looks up zones and devices itself, one step at a time. On: the AI only says what to do and which devices it means, and Jev, a fast TypeSafe model, picks the devices. Faster and cheaper smart-home commands, and a much smaller prompt. Needs a TypeSafe API key.
Get a key at console.typesafe.ai. Without a key the assistant keeps using its own device lookup.

Dump log
Get the app's recent log as a file you can share
Writes the last few thousand log lines — including the detailed satellite, connection and AI-engine logs, whether or not verbose logging is on — to a text file on your Homey and shows a link to it. Open the link on this network, then attach the file to a forum post, an e-mail or a GitHub issue. This is the log to send when reporting a problem: Homey's own diagnostics report only carries the last few lines.

Privacy: API keys and everything that was said (your questions and the assistant's answers) are removed before the file is written, and your home coordinates are rounded to about 10 km. Local network addresses are kept, because they help you see which device the app cannot reach. The file is deleted after 30 minutes.

Remote logging
Send the app's logs to a syslog server
Streams the app's logs to any syslog server on your network or in the cloud (rsyslog, syslog-ng, Synology/QNAP log center, Grafana Alloy/Loki, Papertrail, …) over the standard syslog protocol (RFC 5424). Conversation events are sent as INFO; the detailed per-subsystem logs (ESP connection, AI provider, tools, webserver, …) — which are normally not written to the app's own log — are sent as DEBUG; warnings and errors always ride along. Each subsystem is tagged with its name so you can filter. No token cost — this never touches the AI.
The standard syslog port is 514.
Verbose logging
Write the detailed subsystem logs to the app log
Normally the app log only shows conversation events, so a log you send in cannot say whether the satellite and the AI engine actually connected — the lines that would answer that are the ones being held back. Turn this on to add them: the device connection, the ESP link, the AI provider and the tools. Turn it on, reproduce the problem, then copy the app log (Homey app → More → Apps → AI Voice Assistant → the ⋮ menu). Leave it off the rest of the time — it is a lot of text, and it makes the log harder to read, not easier. No token cost — this never touches the AI.
